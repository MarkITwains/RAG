# Web 界面的设计取舍

**文件**：`src/pcb_rag/webui/index.html`（单文件，约 900 行，含样式与脚本）
**入口**：`GET /` 或 `GET /ui`，由 `dify_external_api.py` 的 `web_ui()` 返回

---

## 一、为什么不用前端框架

三项约束决定了这个选择：

1. **部署形态**。这个系统的使用场景是内网 / 离线机房的 PCB 知识库，装不了 Node 工具链是常态。一个需要 `npm run build` 的前端会让"改一行文案再上线"变成一次完整构建。
2. **改动面**。前端只做三件事：发一个问题、渲染流式文本、列出证据。没有路由、没有全局状态、没有组件复用压力。框架在这里带来的是构建配置而非收益。
3. **可交付性**。单文件意味着可以直接 `pip install` 分发，`pyproject.toml` 里一行 `package-data` 就够；换成框架要处理静态资源指纹、产物目录、版本对齐。

代价也很明确：没有类型检查，没有组件化，复杂交互会很快变得难以维护。一旦界面要长成多页应用（历史会话列表、知识库管理、图谱浏览），应当换 Vue 或 React 重写，而不是在这个文件上继续加。

---

## 二、手写 Markdown 渲染器的边界

答案由 LLM 生成，语法范围是可控的：标题、列表、粗体、行内代码、代码块、引用角标。这六类覆盖了实际输出的绝大部分。

引 `marked.js` 会带来两个问题：离线环境下 CDN 不可用；以及它支持完整 Markdown，反而会让表格、脚注这类渲染出来但样式没定义的结构显得突兀。

当前实现（`md()`）的处理顺序是刻意安排的：

```
转义 HTML → 提取代码块为占位符 → 提取行内代码 → 粗体/标题/列表 → 分段 → 还原占位符 → 角标
```

先把代码块抽成占位符，是为了让后续的粗体、列表、角标正则不误伤代码内容 —— 代码里的 `*` 和 `[1]` 必须原样保留。这是手写渲染器最容易出错的地方，也是最值得记下来的一点。

**已知不支持**：表格、脚注、嵌套列表、引用块。这些结构会被降级成普通段落，不会报错，但排版不好看。若答案里表格变多，应当换用成熟解析器并补样式。

## 三、SSE 的接收方式

`/api/ask/stream` 是 POST，所以不能用 `EventSource`（它只支持 GET）。改用 `fetch` + `ReadableStream` 手动切帧：

```js
buf += decoder.decode(chunk.value, { stream: true });
while ((cut = buf.indexOf("\n\n")) >= 0) {
  handleEvent(buf.slice(0, cut));
  buf = buf.slice(cut + 2);
}
```

两个细节必须保留：

- `decoder.decode(value, { stream: true })`：不加 `stream: true` 会在多字节中文被切断时产生乱码。
- 缓冲区按 `\n\n` 切分而不是按 `read()` 的边界：一个 SSE 事件可能跨多个 chunk，也可能一个 chunk 里含多个事件。

## 四、证据面板为什么是重点

RAG 系统最容易被滥用的地方，是让用户无法区分"文档里写的"和"模型自己知道的"。

因此界面上做了三件事：

1. **证据先于答案到达**。`sources` 事件在检索完成后立刻推送，用户可以先看到命中了哪些文档，再看模型怎么组织语言。
2. **每条证据带定位信息**。文档名、章节、chunk id 前 8 位、检索得分、token 数。得分让"这条为什么排第一"可被质疑，chunk id 让"这条到底在哪"可被追查。
3. **角标可点击**。答案里的 `[n]` 与证据卡一一对应，点击即定位。这比"文末列出参考文献"更直接 —— 用户读到哪句怀疑哪句，当场就能查。

为此在 `sources` 事件里补了 `snippet` / `score` / `tokens` 三个字段。此前只给文件名，用户无法判断证据的实质内容，只能盲信答案。

## 五、鉴权与凭据

服务端用 Bearer Token。界面不绕过它，也不把 Token 写进页面（页面是公开可访问的，注入 Token 等于泄露）。

实际做法：

- Token 存在浏览器 `localStorage`，随请求放进 `Authorization` 头。
- 首次提问返回 401 时，弹出设置面板并给出明确提示，而不是只有一个红色的"请求失败"。
- 未配置 Token 时顶栏显示"未配置凭据"，点击即可打开设置 —— 比显示"索引就绪"却一提问就 401 更诚实。

Token 会随 `localStorage` 留在本机。多人共用一台机器的场景需要注意这一点；若需要更严格的处理，应改为服务端会话 + HttpOnly Cookie。

## 六、已验证的范围

用 Edge CDP（`Page.navigate` → 等待 → `Page.captureScreenshot`）在 1440×900 与 430×880 两个视口下截图核对：

- 空状态：示例问题、说明文案、留白节奏
- 问答态：流式答案的分段渲染、列表、引用角标、证据卡四条的展示与截断（长文档名 ellipsis、`已截断` 标记）
- 窄屏：证据面板隐藏、placeholder 单行、键盘提示隐藏

**未验证**：真实 Milvus 后端下的完整问答（本地未启动 Milvus，接口联调用 mock 替代）、设置面板的保存流程、多轮对话的历史拼接。

Edge 的 `--virtual-time-budget` 不会推进 `fetch` 的 `ReadableStream`，流式截图会停在第一帧（只有一个光标）。必须用 CDP 手动控制截图时机，这一点在写自动化测试时会再遇到。
