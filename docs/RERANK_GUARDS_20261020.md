## 输入与输出

初始召回仍为 200 条，但真正送入 API 的候选最多 50 条；普通配置的 API `top_n` 与本地保留数均为 10。文档使用正文 `MetadataMode.NONE`，保留正文已有的上下文标题，不附带路径、时间戳、父子 ID 等技术元数据。每条最多 1200 字符，查询最多 1000 字符。显式的 top50 消融会返回 50 条，输入上限仍为 50。

未返回的候选分数不再用 0 填充，避免把它们排到负分结果前面。重复或越界索引、缺少结果、非有限分数均视为失败。

## 实际用量与预算

SQLite 账本位于 WSL 用户运行目录。用户最新要求不限制 Rerank 总量，因此生产、正式实验和后续预检的累计 token 与累计请求上限均改为 0（无限制）。此前的 30M/2500 等上限作为历史配置保留，不再生效。所有进程继续共享用量账本，发送前记录预留量，但不会因累计量停止；如果以后显式配置正数，才启用相应上限。

优先读取 SiliconFlow 的 `meta.billed_units.input_tokens` 等返回用量，也支持 `meta.tokens` 和通用 `usage`。接口未报告用量或请求超时时，按 UTF-8 字节数加查询重复与格式开销做保守记账，明确标为估计，不能称为供应商实际扣费。实际 tokenizer/计费仍由供应商决定，本地估计不是精确账单。

每次请求记录候选数、请求 `top_n`、正文与查询长度、实际/估计/本地记账用量、阶段、热身或正式测量、HTTP 状态、`Retry-After`、请求 ID 和服务端限流提示。账本不保存密钥、问题正文或语料。最终导出 `rerank_usage.json`、`rerank_usage.csv` 和逐请求明细，热身与重试也计入总量。

## 停止与限流

402、401、403、预算不足、网络状态不确定和响应格式错误会打开共享停止开关；其他进程在发送前检查该状态。调度器发现后停止工作进程并记录 `halted`，不再退回原始排序后继续整批测量。检索实验遇到第一条请求失败即保留记录并退出，失败/降级数据不能进入有效质量结论。

0 秒间隔不安排主动等待。小样本阶段设 0 次自动 429 重试，以便直接观察服务端；正式阶段最多重试 2 次，服务端 `Retry-After` 和重试过程均保留。不限速正式测试随后收到服务端 `TPM limit reached`，于 20:22 停止；这不是累计 30M 上限触发。恢复时在没有 Retry-After 的 429 后默认退避 60 秒，等待分钟配额窗口，正常请求仍不主动等待。429 重试耗尽仍会停止，402/鉴权保护也继续生效。非零主动间隔的实现跨进程共享。
